Nuclear Energy in the Neighbourhood? Examining Public Support for Small Modular Reactors in the United Kingdom

Research project description

The United Kingdom faces growing demands on its electricity grid, and electricity prices have become a major cost of living issue. At the same time, the UK has made a commitment to transition away from carbon-emitting sources of energy, and to build small modular reactors (SMRs). How SMRs are described and where they are sited can prompt considerations that lead people to support or oppose them.

This project asks: how supportive is the public of SMRs? Does calling SMRs reactors rather than power stations (H1), or placing them in your local area rather than in the United Kingdom (H2) shift support? Does distance to existing nuclear sites shape support for SMRs (H3)? Also, do local area framing effects vary across different parts of the UK (RQ1)?

The core of this project is a survey-based experiment (n = 1,276). The experimental design was a 2x2 factorial design, where as part of the survey question wording, SMRs were either described as reactors or as power stations, and were also described as either being in the participant’s local area or in the United Kingdom.

In addition to these two experimental manipulations, the analysis includes a number of covariates: country (meaning England, Scotland, Wales, and Northern Ireland), basic demographics (sex, age, education), attention to/attitudes toward electricity issues, trust in the electricity industry, trust in government, climate attitudes, left-right political orientations, and proximity to existing nuclear sites.

The main analyses are a set of linear models estimated in a Bayesian statistical framework using brms in R. As robustness checks, the same model specifications are estimated with ordinary least squares (frequentist) estimation; they are also estimated using PyMC and statsmodels in Python.

Data prep

Read in the survey data

The survey experiment was conducted with the Vox Pop Labs online panel between 7 October and 11 November 2025. The data constitute a non-probability sample, so the supplied weights combine quasi-randomization (using the Annual Population Survey as a reference probability sample) with raking on sex, age, education, country of birth, region and 2024 recalled vote to align each each experimental condition with the characteristics of the UK public.

The respondent-level survey data are publicly accessible from the project’s Github repo as a .csv file, and can be read into R directly:

Validate composite measures

Several of the covariates used in the regression models are composite variables comprised of multiple survey items. Validating these composite scores can be approached from multiple angles: inspecting bivariate correlations, reliability analysis (Cronbach’s alpha), and confirmatory factor analysis (CFA). Given that we have weighted survey data, useful functions for this are weights::wtd.cor, survey::svycralpha and the sampling.weights argument in lavaan::cfa.

The survey items measuring attitudes toward electricity issues don’t cohere very well as a composite measure (low inter-item correlations, low Cronbach’s alpha). These will be kept as distict measures in the regression modeling.

Extract factor scores, rescale composite measures

We can use the CFA model to calculate respondent-level factor scores (to use in the regression models as covariates) using the lavaan::lavPredict function. We will want the factor scores (along with the other continous covariates) to be range-standardized (rescaled between 0 and 1) and then mean centred before being entered into the models. This will help with the interpretation of the results: the model intercepts will have a meaningful interpretation, namely the predicted value of the dependent variable when all categorical covariates are set to their reference values, and all continuous variables are set to their (pre-transformation) means.

We will also range-standardize the dependent variable and subtract 0.5; this puts it on a -0.5 to +0.5 scale.

A couple of helper functions range_std and range_centre simplify these variable transformations. Another wtd_summary function helps to sanity-check the resulting transformed variables.

Show code 
range_std <- function(x) {
  x <- (x - min(x, na.rm = TRUE)) / (max(x, na.rm = TRUE) - min(x, na.rm = TRUE))
}

range_centre <- function(x, w = NULL) {
  x <- (x - min(x, na.rm = TRUE)) / (max(x, na.rm = TRUE) - min(x, na.rm = TRUE))
  x <- x - weighted.mean(x, w, na.rm = TRUE)
}

wtd_summary <- function(x, w, na.rm = TRUE, digits = 5) {
  if (na.rm) {
    valid <- !is.na(x) & !is.na(w)
    x <- x[valid]
    w <- w[valid]
  }
  qt <- Hmisc::wtd.quantile(x, w, probs = c(0, .25, .5, .75, 1))
  m <- Hmisc::wtd.mean(x, w)
  out <- c(qt[1:3], Mean = m, qt[4:5])
  names(out) <- c("Min.", "1st Qu.", "Median", "Mean", "3rd Qu.", "Max.")
  round(out, digits)
}

Now we’re finally ready to run some models! The setup for the Bayesian models requires us to specify some priors. Covariate priors are weakly informative. The effects of reactor and local experimental treatments get small negative priors (mean −0.0625, SD 0.05), reflecting H1, H2 and prior experiments showing lower support for nearby plants.

def wtd_alpha(df, cols, wcol="weight"):
    d = df[cols + [wcol]].dropna()
    cov = np.cov(d[cols].to_numpy().T, aweights=d[wcol].to_numpy())
    k = len(cols)
    return k / (k - 1) * (1 - np.trace(cov) / cov.sum())
